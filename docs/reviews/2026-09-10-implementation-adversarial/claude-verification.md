## Additional concurrency and memory verification

**Confirmed inherited concurrent-first-call race:** `packages/core/src/openms/source/CONCEPT/VersionInfo.cpp:112–147` uses a mutable static result plus a separate unsynchronized `is_initialized` bool in `getTime`, `getVersion`, and `getVersionStruct`. C++ protects initialization of each local static object; it does not synchronize the later conditional writes to these already-constructed objects. Two initial callers can concurrently assign/read the strings, structure and bools. The entire source file is byte-identical to baseline commit `ca32296038839459d8c9b075b759e285913d6294` at this path, verified through the parent's retained Git object. Replace each manual guard with a directly initialized `static const` value, using a lambda when trimming is needed. A barrier-synchronized first-call test under ThreadSanitizer is a meaningful follow-up gate; no sanitizer was run here.

**Reject the Qt prohibition claim:** Qt documents `QCoreApplication::processEvents(flags)` as thread-safe and states that it processes the calling thread's events. Calling it from a worker in `TVToolDiscovery.cpp:107` therefore is not itself a forbidden-thread operation. Qt discourages some uses of nested event processing, which is a different concern and does not establish a race here. [Qt's processEvents documentation](https://doc.qt.io/qt-6/qcoreapplication.html#processEvents), inspected 10 September 2026.

**Correct the temporary-file growth description:** `FileTemp.cpp:170–191` appends one filename per automatic temporary-file request and only drains/removes files at static destruction. That is retained cleanup bookkeeping, not proof of lost ownership, but there is no fixed bound on the number of accumulated names during a long-lived process. Claude's “bounded growth” wording is unsupported. Scoped temporary-directory use or explicit cleanup lifecycle can be considered where workload evidence justifies it.

The selected Arrow/Parquet ownership observations are limited source readings, not a memory-safety certificate. They do not replace sanitizer coverage of bindings, desktop lifetime, or the wider scientific library.
